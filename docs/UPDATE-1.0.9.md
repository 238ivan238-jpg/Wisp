# Wisp 1.0.9 — эмодзи по желанию

`app.wisp.voice`, versionCode 10. В настройках «Под ваш голос» появился переключатель «Добавлять эмодзи», выключенный по умолчанию. Долгое нажатие на плавающий микрофон открывает настройки. Лимит записи остаётся пять минут.

Настройка работает с обычным «Чистым текстом» и переводом на английский в обоих способах ввода: рядом с Gboard и в прежней клавиатуре Wisp. Включение эмодзи включает обработку; её выключение отключает эмодзи и перевод. Выключение только эмодзи сохраняет выбранный перевод/обработку. Выбор сохраняется между открытиями приложения, обновление не включает эмодзи автоматически.

Системное правило просит модель добавить не больше одного-двух уместных эмодзи на весь текст. Для формального, серьёзного или сугубо технического текста допустимо не добавлять их. Требования: сохранить смысл и тон, не придумывать эмоции, не заменять слова/числа/пунктуацию/маркеры списка, не дублировать уже имеющиеся эмодзи. Это инструкция модели; автоматической оценки уместности или жёсткого фильтра эмодзи в клиенте нет.

Правило добавляется в существующий запрос редактирования/перевода и сохраняется при смене недоступной модели. Дополнительного сетевого этапа нет. Распознавание Whisper не получает служебную подсказку про эмодзи. Словарь и диктовка остаются JSON-данными, отдельно от системных правил. Без обработки запрос текстовой модели не выполняется, даже при устаревшем флаге эмодзи. При ошибке возвращается исходная расшифровка с предупреждением.

Фикстурные тесты проверяют передачу настройки в оба вида обработки, отключение, резервную модель, Unicode и многострочные списки, сохранение словаря, отсутствие лишних запросов, исходник при ошибке и обход обработки в raw. UI-тест проверяет включение из raw, сохранение после повторного открытия, совместимость с переводом и отключение вместе с обработкой. Эти проверки не оценивают качество выбора эмодзи живой моделью Groq. Проверки на физическом Pixel и живые запросы с пользовательским ключом не выполнялись.
