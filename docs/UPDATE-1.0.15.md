# Wisp 1.0.15 — без декоративного хвоста эмодзи

`app.wisp.voice`, versionCode 16. Пользователь сообщил, что прежнее правило размещения эмодзи не помогло: модель по-прежнему часто добавляет цепочку из пяти смайликов после всего текста. Прежний запрос одновременно просил до 4–6 эмодзи и запрещал общий хвост. Норма количества удалена: теперь важна отдельная подходящая фраза, допустим один эмодзи или ни одного. Добавленные эмодзи допускаются перед/внутри фразы и у начала пункта списка; после последних слов всей диктовки запрещены.

Одной инструкции модели недостаточно. EmojiTailGuard проверяет каждый успешный ответ включённой стилизации в очистке/переводе, включая резервные модели. Удаляется только вновь введённое конечное оформление вне защищённого кода/ссылок. Нет перестановки смайликов по угаданным позициям и дополнительного запроса к модели. Грамматика, слова, числа, отрицания и пунктуация не переписываются этим этапом.

Границы Unicode-графем определяются Android ICU: семейные ZWJ-последовательности, флаги и оттенки кожи обрабатываются целиком. Исходные пользовательские эмодзи защищены по числу вхождений; различие текстового/цветного presentation selector не создаёт лишнюю копию. У добавленного keycap-эмодзи сохраняется базовая цифра или маркер списка. Изначальные эмодзи не удаляются ради запрета хвоста. Префиксы и эмодзи в середине текста остаются на месте. Результат, состоящий только из новых смайликов, возвращает штатный fallback исходного текста вместо пустой вставки.

Выключенная стилизация, raw-режим и исходник при ошибке обработки не фильтруются. Существующие готовые записи восстановления не переписываются задним числом. В диагностике появляется только типизированное событие EMOJI_TAIL_REMOVED, без содержимого, эмодзи или тела ответа. Данные восстановления и статистика сохраняются; интерфейс и разрешения не изменены.

Проверки: `bash scripts/setup-cloud.sh` — release-сборка и подпись v2 успешны, 178 тестов без падений/ошибок/пропусков. Lint debug/release: по 0 ошибок и 13 существующих предупреждений. Фикстуры проверяют русские/английские тексты, оба режима, основную/резервную модель, отсутствие лишнего запроса, защищённый исходник, код/URL, цифры, сложные эмодзи на Android API 28/35 и безопасное логирование. Реальный Groq не вызывался и установка на физическом Pixel не выполнялась. Эти проверки подтверждают работу фильтра на заданных сценариях, но не естественность нового ответа живой модели.
